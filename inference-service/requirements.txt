# YOLO-World's set_classes() requires OpenAI's real CLIP package internally
# (a text encoder for embedding class-name prompts) -- confirmed via
# Ultralytics' own source (ultralytics/nn/tasks.py, WorldModel.set_classes)
# after a live "No module named 'clip'" failure, 2026-08. Must be this git
# URL specifically: the bare PyPI package named "clip" is a different,
# unrelated project and would silently install the wrong thing. Downloads
# CLIP's ViT-B/32 weights to ~/.cache/clip on first real set_classes() call
# (needs internet access at that point) -- persisted via the same
# inference_model_cache volume mount already used for YOLO-World's weights
# (see docker-compose.yml), so this only happens once, not on every
# container restart.
git+https://github.com/openai/CLIP.git
